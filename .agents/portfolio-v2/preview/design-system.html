Gating LLM refactors behind compile and tests

A model can write a refactor that reads well and still breaks the build. The pipeline treats every edit as a claim to be checked.

The Anti-Pattern Resolutor starts from SonarQube findings and asks a model to propose a file-scoped edit that removes the smell without changing behaviour. The interesting part is what happens next: nothing is accepted until mvn compile and the existing test suite both pass.1

The gate

The gate is small on purpose. It answers one question and records why.

gate.py
def gate(change: Change, repo: Repo) -> Verdict:
    """Keep an edit only if the project still builds and its tests pass."""
    if not repo.compiles(change):
        return Verdict.rejected("compile")
    if not repo.tests_pass(change):
        return Verdict.rejected("tests")
    return Verdict.accepted()  # static analysis re-runs later, for reporting only
An edit that reads well is a claim. The build is the evidence.
